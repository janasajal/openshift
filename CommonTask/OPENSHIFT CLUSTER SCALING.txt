OBJECTIVE
---------
Additional worker nodes were added to the cluster in response to increased
workload demand. Pre-scaling validations were performed, MachineSets were
scaled declaratively, and the Cluster Autoscaler was configured to handle
future demand automatically.

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------

request was genuine and not caused by misconfigured resource limits or a
runaway workload.

  master-0.ocp.company.com    820m         21%    6421Mi          40%

  worker-1.ocp.company.com    3680m        92%    27998Mi         87%
  worker-2.ocp.company.com    3820m        96%    29100Mi         91%

  All three worker nodes were found to be operating above 90% CPU and

--------------------------------------------------------------------------------
STEP 6 — MACHINESET SCALING
--------------------------------------------------------------------------------

Each MachineSet replica count was increased from 1 to 2, adding one new
worker node per availability zone. This approach ensured that new nodes
were distributed evenly across zones for high availability.

  Commands used:
  $ oc scale machineset ocp-cluster-worker-us-east-1a \
      -n openshift-machine-api --replicas=2

  $ oc scale machineset ocp-cluster-worker-us-east-1b \
      -n openshift-machine-api --replicas=2

  $ oc scale machineset ocp-cluster-worker-us-east-1c \
      -n openshift-machine-api --replicas=2

  Output observed:
  machineset.machine.openshift.io/ocp-cluster-worker-us-east-1a scaled
  machineset.machine.openshift.io/ocp-cluster-worker-us-east-1b scaled
  machineset.machine.openshift.io/ocp-cluster-worker-us-east-1c scaled

STEP 11 — CLUSTER AUTOSCALER CONFIGURATION
--------------------------------------------------------------------------------

To avoid manual scaling in future demand spikes, the ClusterAutoscaler and
MachineAutoscaler were configured for each zone's MachineSet.

  The ClusterAutoscaler was created with a maximum node cap of 24:

  Configuration applied:
  -----------------------------------------------------------------------
  apiVersion: autoscaling.openshift.io/v1
  kind: ClusterAutoscaler
  metadata:
    name: default
  spec:
    resourceLimits:
      maxNodesTotal: 24
    scaleDown:
      enabled: true
      delayAfterAdd: 10m
      delayAfterDelete: 5m
      delayAfterFailure: 30s
      unneededTime: 10m
  -----------------------------------------------------------------------

  A MachineAutoscaler was created for each zone:

  -----------------------------------------------------------------------
  apiVersion: autoscaling.openshift.io/v1beta1
  kind: MachineAutoscaler
  metadata:
    name: worker-us-east-1a-autoscaler
    namespace: openshift-machine-api
  spec:
    minReplicas: 1
    maxReplicas: 5
    scaleTargetRef:
      apiVersion: machine.openshift.io/v1beta1
      kind: MachineSet
      name: ocp-cluster-worker-us-east-1a
  -----------------------------------------------------------------------

  The autoscaler resources were verified:

  Command used:
  $ oc get clusterautoscaler
  $ oc get machineautoscaler -n openshift-machine-api

  Output observed:
  NAME      AGE
  default   1m

  NAME                              REF KIND     MIN   MAX   AGE
  worker-us-east-1a-autoscaler      MachineSet   1     5     1m
