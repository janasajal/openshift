OVERVIEW
--------
A containerized application deployment was requested by the application team.
The workload was deployed into the dev-team-app namespace using a Kubernetes-
native Deployment object. A ClusterIP Service was configured for internal
communication and an edge-terminated Route was created for external HTTPS
access. Health probes, resource limits, and rollback readiness were also
verified as part of the deployment process.

Note : Deployment (apps/v1) was used instead of DeploymentConfig, as
DeploymentConfig is deprecated in OpenShift 4.x and Deployment is the
recommended Kubernetes-native approach.


--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
STEP 2 : DEPLOYMENT CREATION
--------------------------------------------------------------------------------

A Deployment manifest was prepared with 2 replicas, a RollingUpdate strategy,
resource requests and limits, readiness and liveness probes, and environment
variables sourced from a Secret.

  File : deployment.yaml
  -----------------------
  apiVersion: apps/v1
  kind: Deployment
  metadata:
    name: myapp
    namespace: dev-team-app
    labels:
      app: myapp
      version: v1.0
  spec:
    replicas: 2
    selector:
      matchLabels:
        app: myapp
    strategy:
      type: RollingUpdate
      rollingUpdate:
        maxSurge: 1
        maxUnavailable: 0
    template:
      metadata:
        labels:
          app: myapp
      spec:
        containers:
        - name: myapp
          image: registry.example.com/myapp:v1.0
          ports:
          - containerPort: 8080
          resources:
            requests:
              cpu: "200m"
              memory: "256Mi"
            limits:
              cpu: "500m"
              memory: "512Mi"
          readinessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 10
            periodSeconds: 5
          livenessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 30
            periodSeconds: 10
          env:
          - name: APP_ENV
            value: "production"
          - name: DB_PASSWORD
            valueFrom:
              secretKeyRef:
                name: myapp-db-secret
                key: password

  Command :
  ---------
  $ oc apply -f deployment.yaml

  Output :
  --------
  deployment.apps/myapp created

Notes on probe configuration :
  - readinessProbe : controls when the pod is added to the Service endpoints.
    Without this, traffic is sent to pods before the application is ready,
    which results in 502 errors.
  - livenessProbe  : restarts the container if the application becomes
    unresponsive after startup.


--------------------------------------------------------------------------------
STEP 3 : SERVICE CREATION
--------------------------------------------------------------------------------

A ClusterIP Service was created to provide stable internal DNS-based access
to the application pods. The selector was matched to the app label defined
in the Deployment template.

  File : service.yaml
  --------------------
  apiVersion: v1
  kind: Service
  metadata:
    name: myapp-svc
    namespace: dev-team-app
    labels:
      app: myapp
  spec:
    selector:
      app: myapp
    ports:
    - name: http
      protocol: TCP
      port: 80
      targetPort: 8080
    type: ClusterIP

  Command :
  ---------
  $ oc apply -f service.yaml

  Output :
  --------
  service/myapp-svc created

The Service listens on port 80 and forwards traffic to container port 8080
on all pods matching the label app=myapp.


--------------------------------------------------------------------------------
STEP 4 : ROUTE CREATION
--------------------------------------------------------------------------------

An OpenShift Route was created to expose the application externally. Edge TLS
termination was configured so that HTTPS is handled at the router level. HTTP
traffic is automatically redirected to HTTPS.

  File : route.yaml
  ------------------
  apiVersion: route.openshift.io/v1
  kind: Route
  metadata:
    name: myapp-route
    namespace: dev-team-app
  spec:
    host: myapp.apps.ocp.example.com
    to:
      kind: Service
      name: myapp-svc
      weight: 100
    port:
      targetPort: http
    tls:
      termination: edge
      insecureEdgeTerminationPolicy: Redirect
    wildcardPolicy: None

  Command :
  ---------
  $ oc apply -f route.yaml

  Output :
  --------
  route.route.openshift.io/myapp-route created

TLS termination type used : edge
  - SSL is terminated at the OpenShift Router (HAProxy)
  - Traffic between the router and the pod is unencrypted (internal only)
  - This is the standard approach for most production HTTP workloads
